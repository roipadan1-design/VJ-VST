# Preset bank ("Looks") - proposal for approval

Date: 2026-09-27. Status: **proposal only, nothing built.**

Owner's request: a convenient preset bank; save a look I designed; add to favourites; right-click "save as default".

## 1. What exists today (read from the code)

| Piece | Where | What it means for this request |
|---|---|---|
| 18 **scenes** = JSON files in `engine/Presets/`, generated by `engine/tools/build_instrument_presets.py` | engine `PresetManager::scanPresets` (sorted file list) | A scene is the generative shader + routing. It is **not** what the owner means by "my look". |
| The build script **deletes every `*.json` in `engine/Presets/` that is not in its list** (lines 611-615) | build script `__main__` | Anything saved into `engine/Presets/` would be wiped on the next rebuild. Saved looks must live elsewhere. |
| Scenes are addressed by **index** (`preset` parameter = index + 1) | `PluginProcessor::fireScene` | Indexes shift when a scene is added. A saved look must remember the scene by **name/file**, not number. |
| The picture state the owner designs = plug-in parameters: 8 macros, 13 LOOK knobs + look preset + amount, palette + 3 custom colours, react style + 5 follow toggles, drift/push/softness/shots/hud | `PluginProcessor.cpp` `snapshotParamIds()` | Already collected in one list. |
| **Moments A-D** already save exactly that state (not the scene) and morph back to it | `storeSnapshot` / `recallSnapshot`, PLAY MOMENTS row | ~80 % of "save my look" already works, but only 4 slots, only inside this Live set, no names beyond the recipe, no scene. |
| Macros do **not** reset when the scene changes | processor params persist | Today there is no "this scene's own starting values" concept. |
| All state lives in the Live set (`getStateInformation`); there is no global user folder, no `PropertiesFile` | processor | A bank that survives across projects needs a new small storage location. |
| Live's own "Save as Default Preset" | Live manual | Works for Live's own devices; for a VST it only saves a Live-side .adv. It cannot know about scenes, so we need our own. |

**Feasibility: yes.** No engine change is needed. It is plug-in work: a small file library plus UI. The key definition is:

> **A Look = a scene name + the Moment-style state (macros, LOOK, colour, react, motion) + a name + a star.** Saved as one small JSON file in `Documents\VJ VST\Looks\` (outside the repo, so the build script can never touch it; easy to back up or copy to another machine).

## 2. How comparable tools do it (the conventions we reuse)

- **Lightroom Classic presets panel:** right-click a preset = *Add to Favorites* (a Favourites group always on top) and *Update with Current Settings*.
- **Vital / u-he (Diva, Hive):** star or coloured favourites, user presets kept in a separate *User* folder from factory ones; u-he loads a preset named *default* at start-up.
- **Ableton Live:** *Save Preset* button, hot-swap browsing, right-click device header = *Save as Default Preset*; project-level defaults override global ones.
- **Resolume:** effect presets are values applied on top of an effect instance (same idea as Look = values on top of a scene).
- **NestDrop (VJ):** star favourites, thumbnails, a queue.

So: factory vs user split, a star, favourites-first filter, right-click menus with "Save / Update / Set as default / Rename / Delete". Nothing new to learn.

## 3. The proposed UX (recommended: Option B below)

**Where it lives.** The existing PLAY scene grid gets a 3-cell switch in its header line: `SCENES · LOOKS · ★`. No new panel, no bigger window.
- **SCENES** = today's grid, unchanged.
- **LOOKS** = the same 4-column grid, but the tiles are your saved looks.
- **★** = only the starred looks (favourites) - the set-list view.

**A look tile** (same 109 x 30 size as a scene tile): the name ("Blood Mesh slow"), a small star at the right, and a 3-colour strip along the bottom (its palette), under it in small text the scene it's built on ("Mesh Body"). Hover line: "Blood Mesh slow - Mesh Body · Film · Blood · Pulse. Click = cue, double-click = go."
Thumbnails (a still frame grabbed from the engine) are a **later** add-on; they need an engine-to-plug-in image path.

**Using a look** - identical to scenes: click = cue (NEXT), GO or double-click = switch. On GO the scene switches (with its own musical transition) and the knobs morph to the look over the existing *morph* time. This keeps the owner's cue + GO switching model.

**Saving** (step by step):
1. Design the picture: pick a scene, turn knobs, choose colour/look.
2. Right-click the live scene tile (or any empty area of the LOOKS grid) -> **Save look...**
3. An inline name field appears pre-filled with an automatic name ("Mesh Body · Film · Blood"); type a name or press Enter.
4. The new tile flashes SAVED (the same amber flash the Moments use) and appears in LOOKS.

**Favourite:** click the small star on a look tile (toggle, red when on), or right-click -> *Add to favourites*. Favourites appear first in LOOKS and alone in ★.

**Right-click menu on a look tile:**
- Update with current settings (overwrite this look with what is on screen)
- Rename / Duplicate / Delete (Delete asks once)
- Add to / remove from favourites
- **Set as this scene's default** - every time this scene is fired (from the grid, MIDI or automation) it starts from this look instead of carrying the previous scene's knobs. The scene tile shows a small dot. *Clear scene default* removes it.
- **Set as start-up look** - a new plug-in instance (a new Live set) opens on this look.

**Right-click on a scene tile:** *Save look...*, *Save as this scene's default*, *Reset to factory values* (the scene's own macro defaults).

**Moments stay** as the 4 quick slots inside a song; their right-click gains *Save to library...* so a good moment can become a permanent look.

## 4. Alternatives (a real choice)

| | Layout | Tradeoff |
|---|---|---|
| **A** | A 7th **LOOKS** tab in the EDIT drawer: a full list (name, scene, recipe, star, sort/filter). PLAY does not change at all. | Zero added busyness on PLAY, but the bank is hidden while playing at 760 px - you must open EDIT to reach it. |
| **B (recommended)** | The `SCENES · LOOKS · ★` switch on the existing PLAY grid (section 3). | One tiny new control; looks are playable exactly like scenes with cue/GO. Grid shows 16 at a time (scrolls beyond). |
| **C** | No grid change: click the scene name above the grid -> a popup menu (like a synth's preset dropdown): *★ Favourites*, then looks grouped by scene, then *Save look...*. | Smallest build and nothing on screen changes, but menus are poor for live browsing (no cue state, no colour strip, closes after each pick). |

B and A can be combined later (B to play, A to manage many looks).

**One decision for the owner regardless of layout:** should *Set as scene default* exist (it changes today's behaviour where knobs carry over between scenes), or only *Set as start-up look*? Recommendation: both, since the scene default only applies when you have set one.

## 5. Scope and what changes

**Overall: Medium** (about 2-3 working days for B; A or C about 1.5-2).

- **New `LookLibrary`** (plug-in): reads/writes `Documents\VJ VST\Looks\*.json` (one file per look: name, scene name, values, palette/colours, favourite, created). Also stores `defaults.json` (scene -> look, start-up look). Reuses `snapshotParamIds()` so it saves exactly what a Moment saves.
- **Processor:** `applyLook()` = fire the scene by name + a Moment-style morph to the values (reuse `recallSnapshot`'s morph code); in `fireScene`, apply the scene default if set; in the constructor, apply the start-up look for fresh instances only (never over a loaded Live set).
- **Editor:** grid mode switch + look tiles with star and colour strip; right-click menus; inline rename (the `TextEditor` already planned for Moment rename).
- **Engine: no change.** Build script: no change. Factory scenes stay read-only.
- **Later / optional:** thumbnails (engine frame grab), MIDI "next favourite" action, import/export a bank file.
